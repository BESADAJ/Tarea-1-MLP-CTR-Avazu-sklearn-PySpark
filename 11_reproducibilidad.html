Ejecución de extremo a extremo#

conda env create -f environment.yml
conda activate ml_venv

# 1. Datos: colocar Avazu_x4.zip en data/raw y extraer los tres CSV allí
python scripts/01_ingest.py

# 2. EDA
python scripts/02_eda.py

# 3. scikit-learn
python scripts/03_sk_experiments.py enc 6
python scripts/03_sk_experiments.py tune 6 5
python scripts/03_sk_experiments.py scale 6 100000,1000000,10000000
python scripts/03_sk_experiments.py abl 6

# 4. Spark
bash scripts/run_spark_map.sh
bash scripts/run_spark_seeds_1m.sh

# 5. Benchmark, sin otras cargas en el equipo
bash scripts/run_bench.sh
python scripts/05b_spark_ui.py   # resume la API REST de Spark UI guardada por el punto spark_ui

# 6. Interpretabilidad y prueba final
python scripts/06_interpret.py 10000000
python scripts/07_final_test.py 10000000

# 7. Libro
python scripts/build_notebooks.py
jupyter-book build book

scripts/build_notebooks.py genera book/*.ipynb desde nb_src/*.py, y los capítulos leen las tablas de results/. Por eso el libro se puede reconstruir sin repetir los experimentos. results/sk/runs.jsonl permite reanudar: los ajustes ya registrados no se repiten.

Las ablaciones, la búsqueda de Optuna y la mayor parte de los ajustes con semillas corrieron en paralelo y tardan horas. Los tiempos de los capítulos 4 y 5 dependen de esa carga. Solo los del capítulo 7 son mediciones limpias.

Particularidades de Windows#

Problema

Causa

Solución adoptada

Spark no escribe Parquet

Falta winutils.exe y HADOOP_HOME

DuckDB genera el Parquet. No se instaló el binario de terceros

Spark no lista directorios

Falta la librería nativa de Hadoop

read_avazu() pasa rutas exactas de archivo, con basePath

Python workers fallan

PySpark 4.0.1 no lee error-conditions.json dentro de pyspark.zip

Sin UDF, y sin createDataFrame desde Python

No se guardan modelos Spark

Mismo problema de escritura

Las predicciones se devuelven por Arrow a data/final

En Linux, estos cuatro problemas no aplican.
